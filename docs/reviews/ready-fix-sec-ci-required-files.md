## ما فيه

1. **الفحص الآلي لا ينجح دون تدقيق:** `.github/workflows/ci.yml`.
   - خطوة «التحقق من اكتمال التأسيس» تذكر كل ملف غائب من `composer.lock` و`package-lock.json` و`phpstan.neon` برسالة خطأ، ثم تنتهي بـ `exit 1`.
   - حُذف شرط التخطي `if: steps.boot.outputs.ready == 'true'` من الخطوات التسع، فلا تُتخطى بعد اليوم.
   - جُرّب منطق الخطوة محلياً: بملف غائب تنتهي بـ 1، وبالملفات الثلاثة بـ 0.
2. **قاعدة حماية الفرع الرئيسي (تحقق فقط، لا تغيير في إعدادات المستودع):** عبر GitHub API.
   - `branches/main/protection` ترد 404 «Branch not protected»، لأن الحماية ليست بالطريقة القديمة بل بقاعدة (Ruleset).
   - القاعدة «حماية main» (رقم 24976299) مفعّلة (`active`) على الفرع الافتراضي، وبلا مستثنين (`bypass_actors` فارغة).
   - فيها: منع الحذف، ومنع الدفع القسري، وطلب دمج إلزامي، و**فحص «الجودة والاختبارات» إلزامي**، واسمه يطابق اسم العمل في `ci.yml`.
   - **ملاحظة:** عدد الموافقات المطلوبة صفر، فمراجعة المشرف وصفوان قبل الدمج عرف لا تفرضه GitHub. رفعه قرار لصفوان، ولم يُغيَّر.
3. **سجل القرار:** مدخل 14 أكتوبر في `docs/decisions.md`.

- `fails the CI run when a lock file or the phpstan config is missing`: الخطوة تذكر الملفات الثلاثة وفيها `exit 1`.
