# مشغّل الفحص الآلي المحلي

منذ 26 أكتوبر 2026 ترفض GitHub تشغيل مهام Actions على خوادمها لتعثّر الدفع في الحساب. فصار الفحص يعمل على جهاز صفوان بمشغّل مستضاف ذاتياً، ولا يستهلك دقائق مدفوعة (قرار 27 أكتوبر في `decisions.md`). ومنذ 0.14.1 صار المشغّل **مؤقتاً**: حاوية جديدة لكل مهمة، تُلغى بعدها (قرار 28 أكتوبر).

## كيف يعمل

- الملفات في `deploy/ci-runner/`:
  - `compose.yaml`: الحاويتان.
  - `Dockerfile`: صورة المشغّل.
  - `entrypoint.sh`: التسجيل المؤقت لمهمة واحدة، وإلغاء تسجيل دائم قديم.
  - `register.sh`: الحلقة على الجهاز، تجلب رمز تسجيل جديداً قبل كل مهمة.
- **حاوية `runner`:** صورة GitHub الرسمية `ghcr.io/actions/actions-runner` بإصدار مثبّت، ومعها shellcheck. وفيها Docker CLI وbuildx، وsudo بلا كلمة مرور يحتاجه `setup-php`.
- **مؤقت (`--ephemeral`):**
  - `register.sh` يطلب رمز تسجيل جديداً (مدته ساعة)، ثم ينشئ حاوية بـ `docker compose run --rm`.
  - الحاوية تفرّغ مجلد العمل والمؤقت، وتسجّل نفسها مؤقتاً، وتنفّذ مهمة واحدة. ثم تلغي GitHub تسجيلها، وتخرج الحاوية وتُحذف.
  - ثم يعيد `register.sh` الكرّة. فلا يبقى من مهمة في حاوية المشغّل شيء لما بعدها: لا ملفات ولا تسجيل ولا عملية.
  - **وقبل كل مهمة يعيد `register.sh` إنشاء خادم Docker الخاص (dind) ومجلديه** (`docker-data` و`work`): فلا يبقى مما فعلته مهمة شيء للتي بعدها، لا حاوية ولا مجلد ولا شبكة ولا swarm ولا إضافة، ولا ملف في قرص dind، ولا طبقة صورة عُدّلت في مخزنه. ولا تبدأ مهمة إن تعذّر. وثمنه تنزيل الصور في كل مهمة (دقائق قليلة).
  - **الحلقة تُشغَّل مرة واحدة:** حلقتان معاً تحذف إحداهما ملفات مهمة الأخرى، وتطرد تسجيلها بالاسم نفسه.
  - والرمز يمر إلى الحاوية من دخلها القياسي، لا متغير بيئة (فلا يظهر في `docker inspect`)، ولا يُكتب في ملف.
- **حاوية `dind`:** خادم Docker خاص بالمشغّل (`docker:<إصدار>-dind`)، دائمة. والمشغّل يشاركها شبكتها، ويكلّمها على `127.0.0.1:2375`. فيلزم:
  - خدمات الفحص (PostgreSQL وRedis) ومنافذ `docker run -p 127.0.0.1::` تُفتح على `127.0.0.1` الذي يراه المشغّل، كما على `ubuntu-latest`. ولا تتعارض مع منافذ بيئات التطوير (5432 و6379 وغيرها).
  - مجلد العمل والمؤقت (`TMPDIR`) على المسار نفسه `/ejaz-ci` في الحاويتين. فيصح `docker run -v "$PWD/...:..."` و`mktemp -d` في الخطوات.
  - حاويات الجهاز (التطوير والعرض) خارج متناول سير العمل.
  - والخادم ومجلداه جديدة لكل مهمة، فالصور تُنزَّل في كل مهمة.
- **التوجيه:** `runs-on: ${{ vars.CI_RUNNER || 'ubuntu-latest' }}` في `.github/workflows/ci.yml`.
  - متغير المستودع `CI_RUNNER=ejaz` يرسل المهام إلى هذا المشغّل.
  - وحذفه يعيدها إلى خوادم GitHub بلا تعديل في الشيفرة.
- **الاسم والتسميات:** `ejaz-local`، بالتسميات `self-hosted` و`Linux` و`X64` و`ejaz`.

## التشغيل والإيقاف

```bash
bash deploy/ci-runner/register.sh     # الحلقة: تبقى تعمل في نافذتها، وكل مهمة في حاوية جديدة
```

- **الإيقاف:** Ctrl+C في نافذة الحلقة، ثم `docker compose -f deploy/ci-runner/compose.yaml stop`. والمهام تنتظر في GitHub حتى تعود.
- **السجل:** نافذة الحلقة نفسها. و`docker compose -f deploy/ci-runner/compose.yaml ps` يعرض `dind` دائماً، ومعها حاوية المشغّل وقت انتظار مهمة أو تنفيذها.
- **بعد إعادة تشغيل الجهاز** لا تعود الحلقة وحدها، لأنها على الجهاز لا في Docker (فهي التي تملك بيانات GitHub). **وتُشغَّل يدوياً** بالأمر أعلاه عند الحاجة إلى فحص، بلا مهمة مجدولة في ويندوز (قرار صفوان، 28 أكتوبر 2026): فلا يعمل على الجهاز شيء من سير العمل إلا وصفوان يعلم.

- **المشغّل واحد:** المهام تُنفَّذ واحدة بعد واحدة.
  - كل دفع إلى فرع له طلب دمج يشغّل الفحص مرتين (`push` و`pull_request`).
  - ولا يُلغى أحدهما: قواعد `main` ترفض الدمج إن كان فحص «الجودة والاختبارات» ملغى، ولو نجح الآخر.
  - مدة «الجودة والاختبارات» نحو مدة `composer check` على الجهاز.
- **والجهاز مطفأ أو Docker Desktop متوقف أو الحلقة متوقفة:** لا فحص. والمهام تبقى في الطابور حتى 24 ساعة، ثم تُلغى فيُعاد تشغيلها.

## الانتقال من المشغّل الدائم (قبل 0.14.1)

مرة واحدة:

```bash
bash deploy/ci-runner/register.sh remove   # يلغي التسجيل الدائم القديم، ويوقف حاوية المشغّل القديمة وdind ويحذفهما، ويحذف مجلد التسجيل state وحده
bash deploy/ci-runner/register.sh          # الحلقة المؤقتة
```

- **قبله:** أوقف الحلقة إن كانت تعمل، وانتظر أن يفرغ المشغّل من مهمته. فـ GitHub ترفض إلغاء تسجيل مشغّل ينفّذ مهمة («is currently running a job and cannot be deleted»)، ولا يتغير شيء حينها، فيُعاد الأمر بعد انتهائها.
- **مجلدا `docker-data` و`work`** لا يحذفهما: الحلقة تعيد إنشاءهما قبل كل مهمة.

## الرمز

- يُطلب من `gh api -X POST repos/SAFWANALASMAR/ejaz-portal/actions/runners/registration-token` إن وُجدت `gh`، وإلا ببيانات git المحفوظة لـ github.com (صلاحية `repo`).
- **رمز جديد قبل كل مهمة**، مدته ساعة. لا يُطبع ولا يُكتب في ملف، ويمر إلى الحاوية من دخلها القياسي.
- **لاسم آخر:** `RUNNER_NAME=<الاسم> bash deploy/ci-runner/register.sh`.

## التحديث

- **تحديث المشغّل:** يحدّث نفسه داخل الحاوية حين تصدر GitHub إصداراً. ولأن الحاوية جديدة لكل مهمة، فالأفضل تثبيت الإصدار الأحدث في الصورة.
- **لتثبيت إصدار أحدث:** يُغيَّر الوسم في `Dockerfile` و`image:` في `compose.yaml` معاً. والحلقة تبني الصورة عند بدئها.
- **إصدار dind:** يُغيَّر في `compose.yaml`، ويُبقى قريباً من إصدار Docker CLI في صورة المشغّل.

## العودة إلى خوادم GitHub

1. حذف متغير المستودع `CI_RUNNER`.
   - بـ `gh variable delete CI_RUNNER`.
   - أو من الإعدادات: Settings ← Secrets and variables ← Actions ← Variables.
2. ثم إيقاف الحلقة، و`docker compose -f deploy/ci-runner/compose.yaml down`.

## الأمن

- **لا شيفرة من خارج المستودع:**
  - المستودع خاص، وطلبات الدمج من النسخ (forks) لا تشغّل سير العمل أصلاً. والإعداد في Settings ← Actions ← General ← Fork pull request workflows، وفيه `run_workflows_from_fork_pull_requests: false`. **ولا يُفعَّل هذا الخيار ما دام المشغّل محلياً.**
  - وفي `ci.yml` شرط على المهمتين أيضاً: طلب الدمج يُفحص إن كان فرعه في المستودع نفسه وحده (`github.event.pull_request.head.repo.full_name == github.repository`)، فلا يكفي خطأ في الإعداد.
  - **ولا Dependabot** (`github.actor != 'dependabot[bot]'`، ولا فرع يبدأ بـ `dependabot/` ولو دفع إليه إنسان أو ضغط «Update branch»): تحديث مكتبة لم يراجعه أحد لا يعمل على الجهاز. وفحصه يظهر «متخطى» (skipped)، وGitHub تقبله في القواعد، فـ **لا يُدمج طلب Dependabot بلا فحص محلي يدوي** (`composer check` في نسخة عمل).
- **لا سكربتات تثبيت ولا إضافات Composer:** `composer install --no-plugins --no-scripts` ثم `composer run-script --no-plugins post-autoload-dump` صراحة، و`npm ci --ignore-scripts`. وشيفرة المكتبات في الاختبارات والبناء تعمل كما في كل فحص، فالحماية منها في الشرطين أعلاه.
- **مؤقت وجديد:** كل مهمة في حاوية مشغّل جديدة، وخادم Docker خاص جديد بمجلدين جديدين. وتسجيل المشغّل الدائم القديم لا يُركَّب في حاوية مهمة.
- **أي شيفرة في سير العمل** على فرع في المستودع تعمل على جهاز صفوان.
  - وحاوية dind ممتازة (`privileged`)، فما يعمل فيها يقدر على آلة Docker Desktop الافتراضية.
  - ولا يُستعمل هذا المشغّل لمستودع عام، ولا يُضاف إلى مستودع آخر (`decisions.md`).
- **لا أسرار للمستودع على المشغّل:** سير العمل لا يستعمل أسراراً. ورمز `GITHUB_TOKEN` للقراءة وحدها (`permissions: contents: read`).
