# سير العمل

دليل للمطور الذي يتسلم المشروع: كيف تعمل البيئة، وكيف تُبنى الميزة من الفرع إلى الدمج، وكيف تسير الطلبات والحالات داخل البوابة.

## خريطة الوثائق

- `CLAUDE.md` — دستور المشروع وقواعده الذهبية. يقرؤه كلود كود في كل جلسة، وهو ملزم للمطور البشري أيضاً.
- `docs/overview.md` — الجمعية، والمستخدمون، والمتطلبات الحاكمة.
- `docs/architecture.md` — الطبقات، ومكان كل شيء، وقواعد الشيفرة.
- `docs/requirements/` — متطلبات كل وحدة وشروط قبولها، ملف لكل وحدة.
- `docs/security.md` و`docs/performance.md` — إلزاميان في كل ميزة.
- `docs/design/ui-reference.md` — المرجع البصري الملزم وصور التصميم.
- `docs/roadmap.md` — المراحل وحالة كل بند.
- `docs/decisions.md` — كل قرار معماري وسببه والبدائل المرفوضة.
- `docs/open-questions.md` — ما ينقص من الجمعية. لا يُخترع محتوى، بل يوضع مكانه 【ناقص】.
- `docs/progress-log.md` — سجل كل جلسة عمل.
- `docs/reviews/` — مراجعات المشرف الخارجي وردود التنفيذ عليها.

## البيئة المحلية

كل شيء في حاويات Docker، فلا يُثبَّت PHP ولا Node على الجهاز.

**الخدمات (`compose.yaml`)**
- `app`: لارافيل على `http://localhost:8000`، ولوحة الإدارة على `/admin`.
- `queue`: Horizon للمهام الخلفية، ولوحته على `/horizon` للمشرف العام.
- `scheduler`: المهام المجدولة في `routes/console.php`، ومنها مسح سجل العمليات بعد مدة الاحتفاظ. وفي الإنتاج تحل محلها مهمة cron كل دقيقة: `php artisan schedule:run`.
- `vite`: الواجهة أثناء التطوير.
- `pgsql`: قاعدة البيانات `ejaz` (وقاعدة الاختبارات `ejaz_testing`).
- `redis`: الجلسات والذاكرة المؤقتة والطوابير.
- `mailpit`: البريد التجريبي على `http://localhost:8025`.
- `browser`: اختبارات المتصفح، ولا تعمل تلقائياً.
- منافذ `pgsql` و`redis` و`mailpit` على هذا الجهاز وحده (`127.0.0.1`)، فلا تصلها أجهزة الشبكة. ولتغيير رقم المنفذ: الرقم وحده في `.env` (`FORWARD_DB_PORT=5433`)، بلا عنوان.

**أول مرة:** `bash scripts/setup.sh`، ثم `docker compose exec app php artisan ejaz:create-admin` لإنشاء المشرف العام، ثم الدخول وتفعيل التحقق الثنائي (شرط لدخول اللوحة).

**يومياً:** `docker compose up -d`.

**ملاحظات ويندوز**
- `vendor` والقوالب المترجمة على أقراص Docker لا على قرص ويندوز، للسرعة. بعد سحب تغيير في `composer.lock` نفّذ `docker compose exec app composer install`.
- إن لم تظهر تعديلات القوالب في المتصفح، اجعل `VITE_POLLING=true` في `.env`، أو أعد تشغيل `vite`.

## الأوامر

```bash
docker compose exec -T app php artisan test           # الاختبارات
docker compose exec -T app composer check             # التنسيق + التحليل الثابت + الاختبارات
docker compose exec -T app composer audit             # ثغرات مكتبات PHP
docker compose exec -T vite npm audit --omit=dev      # ثغرات مكتبات الواجهة
docker compose exec -T vite npm run build             # بناء الواجهة
docker compose logs -f app                            # سجل الأخطاء
```

اختبارات المتصفح ولقطات الشاشات: `tests/browser/README.md`.

## بناء ميزة من البداية إلى الدمج

1. **البند والمتطلبات:** حدد البند في `docs/roadmap.md`، واقرأ وثيقته في `docs/requirements/`، وما يخصه من الحماية والأداء والتصميم.
2. **الصورة المرجعية:** إن كانت للميزة شاشة، افتح صورتها في `docs/design/` قبل البناء.
3. **الفرع:** `git switch -c feature/<اسم-مختصر>` (أو `fix/` أو `docs/` أو `chore/`).
4. **الاختبارات أولاً** لشروط القبول: المسار السعيد، والرفض بلا صلاحية، والمدخل الخاطئ، والوصول لسجل الغير (IDOR).
5. **التنفيذ بالترتيب:** الترحيلات والنماذج والحالات (Enums)، ثم Actions، ثم Policies، ثم Form Requests، ثم المتحكمات أو Livewire، ثم شاشات Filament. والنصوص في `lang/ar/<الوحدة>.php`.
6. **الفحص:** `composer check` ناجح، وللشاشات اختبار متصفح ولقطات على ثلاثة عروض.
7. **الحفظ:** حفظ بعد كل جزء ناجح، برسائل Conventional Commits بالإنجليزية.
8. **التوثيق:** حالة البند في `roadmap.md`، وكل قرار في `decisions.md`، وكل ناقص في `open-questions.md`.
9. **طلب الدمج:** `gh pr create` بوصف بالعربية: ما أُنجز، وكيف يُجرَّب، وما بقي.
10. **المراجعة:** لا دمج قبل موافقة المشرف وصفوان. والملاحظات تُطبق وتُرد كل واحدة بما فُعل.
11. **نهاية الجلسة:** سجل في `docs/progress-log.md`.

## قواعد لا تُكسر

- لا محتوى مخترع للجمعية: أرقام، أو أسماء، أو تواريخ، أو نصوص رسمية.
- لا أسرار في الشيفرة ولا في قيت. كل مفتاح في `.env`، ومثاله الفارغ في `.env.example`.
- لا يُعدَّل ملف ترحيل دُمج في main، بل يُنشأ ترحيل جديد.
- لا مكتبة جديدة دون قرار مسجل وموافقة صفوان.
- كل مسار له صلاحية، وكل مدخل له تحقق، وكل عملية إدارية تُسجَّل في سجل العمليات.
- الذاكرة المؤقتة تخزن مصفوفات لا كائنات (لارافيل 13 يمنع استرجاع الكائنات منها).

## سير العمل داخل البوابة

الحالات تُعرَّف بـ Enums، وكل انتقال بينها Action يتحقق من الصلاحية ويُسجَّل. الوحدات المعلَّمة «مخطط» لم تُبنَ بعد، وتُفصَّل هنا عند بنائها.

**الحساب (منجز)**
1. التسجيل بالاسم والبريد والجوال السعودي وكلمة المرور، مع الموافقة على سياسة الخصوصية. يأخذ الحساب الدور `member`.
2. يُرسل رمز الجوال فوراً، ورابط توثيق البريد في الخلفية.
3. توثيق الجوال شرط للتقديم في المسابقات.
4. الأدوار الإدارية تُمنح من المشرف العام فقط، ويُسجَّل المنح. والتحقق الثنائي إلزامي للأدوار الحساسة.
5. طلب حذف الحساب: يسجله المستخدم بكلمة مروره، ثم يعالجه المشرف العام بإخفاء البيانات الشخصية مع حفظ ما يلزم نظاماً.

**الطلبات الإلكترونية (مخطط — `requirements/02-e-services.md`)**
- مُستلم ← قيد المراجعة ← بحاجة لاستكمال ← مقبول أو مرفوض ← مغلق.
- يُشعَر المتقدم عند كل تغيير. والانضمام للجمعية العمومية يمنح دورها بعد اعتماد مسجَّل.

**التسجيل في البرامج (مخطط — `requirements/03-programs-courses.md`)**
- مسجَّل أو في قائمة الانتظار ← حاضر أو متغيب ← شهادة.
- المقاعد بقفل في قاعدة البيانات، لا عدّ في الذاكرة.

**المسابقات (مخطط — `requirements/06-competitions.md`)**
- مسودة ← مُقدَّم ← مُصحَّح آلياً ← مُسند لمحكّم ← مُقيَّم ← نتائج معتمدة (تُقفل الدرجات) ← سحب بسجل ثابت.

**المحاضر (مخطط — `requirements/04-general-assembly.md`)**
- مسودة ← معتمد، ولا يراها الأعضاء قبل الاعتماد.

**المدفوعات (مخطط — `requirements/08-store-payments.md`)**
- معلّقة ← مدفوعة أو فاشلة ← مستردة. والتحقق من الخادم بتوقيع الإشعار، ومنع تكرار المعالجة.

**المحتوى العام (المرحلة 1)**
- مسودة ← منشور، بيد محرر المحتوى. ويُمسح التخزين المؤقت للصفحات العامة عند كل تعديل.

بيئتا التجريبي والإنتاج داخل المملكة، ومزود الاستضافة قيد القرار (`decisions.md`). يُوثَّق هنا عند حسمه: المتغيرات، والنسخ الاحتياطي، والمراقبة، وخطوات النشر.
