# دليل المراجع الفني — بوابة جمعية إعجاز

هذا الدليل لمن يراجع الشيفرة لأول مرة. يشرح ما يُراجَع، وكيف يُشغَّل، وأين الأدلة على كل ادعاء في المشروع. والإصدار المرجعي للمراجعة هو الوسم `v0.10.0` على الفرع `main`.

## ١. المشروع باختصار

إعادة بناء موقع ejaz.sa (كان ووردبريس) إلى بوابة خدمات متكاملة: حسابات وصلاحيات، ولوحة إدارة، وحوكمة، ومكتبة، وبرامج ودورات، وجمعية عمومية، ومسابقات، وطلبات إلكترونية، ونماذج ومستندات. والتصميم يستهدف 30,000 مستخدم.

- **التقنيات:** Laravel 13 · PHP 8.4 · Filament 5 (لوحة الإدارة على `/admin`) · Livewire 4 · قوالب Blade للواجهة العامة · Tailwind CSS 4 · PostgreSQL 17 · Redis 7 · Horizon · Docker Compose.
- **الواجهة:** عربية من اليمين إلى اليسار، تُولَّد من الخادم وتتنقّل بين صفحاتها بـ `wire:navigate` (بلا فصل للواجهة عن الخادم، وبلا إطار JavaScript). والملفات والدخول والدفع وما خارج الموقع تحميل كامل (`App\Support\SpaLink`). ولوحة الإدارة تعمل بوضع التنقّل السريع في Filament (`->spa()`).
- **الحجم التقريبي:** نحو 680 ملف PHP في `app/`، و51 ترحيلاً، و128 ملف اختبار Pest، و10 ملفات سيناريوهات متصفح Playwright.

## ٢. التشغيل في خمس دقائق

```bash
bash scripts/setup.sh      # أول مرة: ينشئ .env وكلمات المرور المحلية العشوائية ويبني الحاويات ويشغّل الترحيلات
docker compose up -d
```

- الموقع: http://localhost:8000 — لوحة الإدارة: http://localhost:8000/admin — البريد التجريبي: http://localhost:8025
- حساب تجربة محلي: `docker compose exec app php artisan ejaz:demo-user --admin` (يعمل في البيئة المحلية فقط، وكلمة المرور ومفتاح التحقق الثنائي عشوائيان في كل تشغيل).
- كل المنافذ مربوطة على `127.0.0.1` عمداً، فلا تُفتح البوابة من جهاز آخر في الشبكة.
- التفصيل: `دليل-التشغيل.md`.

## ٣. بوابات الجودة (كلها تعمل في الفحص الآلي على GitHub عند كل طلب دمج)

```bash
composer check   # Pint (التنسيق) + Larastan المستوى 6 + كل اختبارات Pest
npm run build
```

- **الاختبارات:** أكثر من 2,000 اختبار Pest، تشمل اختبارات رفض صريحة لكل صلاحية (من لا يملك الصلاحية يُرفض).
- **المتصفح:** Playwright على ثلاثة مقاسات (1440 و820 و390) مع فحص إمكانية الوصول (axe). التشغيل: `tests/browser/README.md`.
- **الفحص الآلي:** `.github/workflows/ci.yml` — أدوات GitHub مثبتة ببصماتها لا بأرقام إصداراتها، وتدقيق اعتماديات npm يوقف البناء عند الثغرات العالية، وفحص الملفات الإلزامية لا يمكن تجاوزه.
- **حماية `main`:** لا دمج إلا بطلب دمج ونجاح الفحص.

## ٤. البنية وأين تبدأ القراءة

القاعدة: المتحكّمات رفيعة، والمنطق كله في Actions.

- `app/Actions/<الوحدة>/` — منطق العمل، كل إجراء صنف بدالة `handle()`. ابدأ من هنا.
- `app/Policies/` — الصلاحيات، وكل إجراء حساس يعيد فحصها بنفسه ولا يعتمد على الواجهة.
- `config/permissions.php` — مصفوفة الأدوار والصلاحيات (المصدر الوحيد لها).
- `app/Enums/` — الحالات (طلب، مسابقة، دفع...) بانتقالات محددة.
- `app/Http/Requests/` — التحقق من المدخلات.
- `app/Filament/` — لوحة الإدارة.
- `resources/views/` — الواجهة العامة، والنصوص العربية في `lang/ar/` لا داخل القوالب.
- `database/migrations/` — قيود حقيقية في القاعدة (مفاتيح أجنبية، وقيود CHECK، ومشغّلات تمنع تعديل السجلات الملحقة فقط).

خريطة أعمق: `docs/architecture.md`، والقرارات وأسبابها: `docs/decisions.md`.

**عيّنة مقترحة للمراجعة السريعة** (تمثّل أسلوب المشروع):

1. `app/Actions/Competitions/ApproveDrawVoid.php` و`RejectDrawVoid.php` — قفل الصفوف، ومنع الموافقة على طلبك بنفسك من ثلاث جهات (السياسة، والإجراء، وقيد CHECK في القاعدة).
2. `app/Auth/LoginRateLimiter.php` — حدود الدخول قبل تجزئة كلمة المرور، لكل حساب ولكل شبكة وللبوابة كلها.
3. `app/Policies/FormEntryPolicy.php` و`app/Models/FormEntry.php` (`scopeVisibleInPanel`) — حصر رؤية البيانات الشخصية.
4. `app/Actions/Accounts/PruneUnverifiedAccounts.php` — حذف الحسابات المتروكة مع إعادة الفحص تحت القفل.
5. `app/Support/PrivateFileResponse.php` — تقديم الملفات الخاصة بروابط موقّعة وترويسات آمنة.

## ٥. الأمن وحماية البيانات

- `docs/security.md` — النموذج الأمني كاملاً.
- `docs/security/` — تقارير الفحص الأمني (10 و12 أكتوبر) وفحص OWASP ZAP المحلي (13 أكتوبر).
- `docs/reviews/` — تقرير جاهزية لكل فرع دُمج، ومنها تقريرا مراجعة التكامل المستقلة (14 و15 أكتوبر): الأولى وجدت ملاحظة عالية ومتوسطتين وأُصلحت كلها، والثانية بلا ملاحظات حرجة أو عالية أو متوسطة.
- **حماية البيانات الشخصية (نظام PDPL):** إخفاء هوية الحساب عند حذفه، وحذف البيانات بعد مدة احتفاظ يضبطها المشرف، وإعادة الإخفاء بعد استعادة نسخة احتياطية (`ejaz:reapply-anonymization`)، وتنظيف الملفات اليتيمة (`ejaz:prune-orphan-private-files`).
- **أرقام الهوية:** تُخزَّن مشفّرة مع بصمة للبحث، ولا يحوي المستودع أي بيانات حقيقية (أرقام الاختبارات وهمية).

## ٦. ما لم يُبنَ بعد أو يُنتظر فيه قرار (بصراحة)

- **المساعد الذكي:** لم يُبنَ (`docs/requirements/10-ai-assistant.md`).
- **الدفع الإلكتروني:** مبني ومؤرشف خلف مفتاح معطّل، والمشغّل التجريبي يرفض العمل في الإنتاج. لا يلزم للإطلاق.
- **قرارات تنتظر الجمعية** (`docs/open-questions.md`): مدد الاحتفاظ بالبيانات، ونسبة النصاب، ومزوّد واتساب، وغيرها. النظام لا يحذف شيئاً قبل تحديد المدد.
- **لم يُنشر على خادم إنتاج بعد.** خطوات النشر جاهزة في `docs/deploy.md` و`docs/deploy/readiness.md`.
