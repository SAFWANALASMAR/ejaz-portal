# تجربة النسخ الاحتياطي على تخزين S3 محلي

تشغّل `scripts/backup.sh` فعلياً بصورة النسخ الحقيقية (`deploy/docker/Dockerfile`، المرحلة `backup`)، على خادمَي MinIO:
- `contabo`: حاوية الملفات الخاصة، بمستخدم قراءة وحدها.
- `hetzner`: حاوية النسخ بقفل الكائنات (فالإصدارات معه)، بمستخدم كتابة وسرد بلا حذف ولا قراءة، وبلا SSE-S3 كـ Hetzner.

```bash
bash tests/backup/run.sh     # من جذر المشروع (Git Bash أو لينكس)، ويطبع PASS أو FAIL لكل فحص
```

- مشروع compose مستقل (`ejazbackuptest`) بلا منافذ على الجهاز، ويُزال بحاوياته وبياناته عند الانتهاء.
- MinIO أُرشف ولا تُوزَّع صوره ولا ملفاته، فيُبنى من مصدره بإصدار مثبت في الحجم `ejazbk-minio-bin` في أول تشغيل (دقائق).
- ما يُثبته: السكربت قبل الإصلاح يفشل بـ `--sse`، والجديد ينجح (يوماً عادياً ويوم تجديد وبعد حذف ملف وبعد تغييره)، ولا اسم ولا محتوى مقروء في `files/`، ولا SSE على الكائنات، والتجديد وحده يرفع إصداراً جديداً، والمفتاحان مقيّدان، والاستعادة بـ rclone تعيد الملفات مطابقة (sha256)، ونسخة القاعدة تُفك بالمفتاح الخاص.
- ليس جزءاً من `composer check` ولا من الفحص الآلي، لأنه يبني صورة النسخ ويشغّل Docker.
